## Causa-raiz confirmada (detalhamento tecnico)

- Bug introduzido parcialmente por `0802982`. Antes desse commit,
  `defaultProjectRoot()` retornava `QDir::currentPath()` quando nao achava um
  projeto. Isso quebrava instalacoes (app em `Program Files`, current dir sem
  permissao de escrita). O fix trocou para `~/.ssaconsultarapida` - correto
  em espirito. Mas o caminho do banco e `<root>/data/ssas.db`
  (`StartupOptions.cpp:139-141`), e o `mkpath` em `main.cpp:73-80` so rodou
  para `<root>`, nao para `<root>/data`. Ficou um GAP de um nivel de
  diretorio. SQLite `OPEN_CREATE` so cria o arquivo, nao o diretorio pai.
- Cadencia exata da falha:
  1. `app/desktop/main.cpp:73-80` cria `~/.ssaconsultarapida/` mas nao o
     subdir `data/`.
  2. `src/platform/StartupOptions.cpp:139-141` resolve
     `databasePath = ~/.ssaconsultarapida/data/ssas.db`.
  3. `src/infra/sqlite/SqliteActivityAnalyticsInitializer.cpp:245` abre o DB
     em `ReadWrite` (sem CREATE) no startup -> lanca `runtime_error`.
  4. O catch em `DesktopMainViewModelFactory.cpp:128-134` engole esse erro
     como "Activity analytics unavailable" (logado em `qWarning`). A janela
     abre, mas analytics fica desabilitado.
  5. `Main.qml:320-322` chama `vm.browse.load()` em `Component.onCompleted`.
  6. `SqliteSsaRepository` abre ReadOnly (`SqliteConnection` default) ->
     lanca -> `PageQueryCoordinator.cpp:330-348` emite
     "Falha ao consultar dados".
  7. Se o usuario tentar `Importacao > Importar XLSX externo`, o
     `SpreadsheetImportWorkflowPort.cpp:1344-1346` abre `WriteSession` em
     `ReadWriteCreate` (`SqliteSsaImportWriter.cpp:711`), mas SQLite
     `OPEN_CREATE` nao cria diretorio. `sqlite3_open_v2` retorna
     `SQLITE_CANTOPEN`, lanca `runtime_error`, capturado em
     `SpreadsheetImportWorkflowPort.cpp:1450-1475` -> `reason="operation_failed"`.
  8. `WorkflowCommandViewModel.cpp:124-126` mapeia `operation_failed` ->
     "falha operacional" para cada arquivo do lote de 64.

## Por que o bug nao foi pego pelos testes

- Os testes sempre fazem `create_directories(dbPath.parent_path())` antes de

- O smoke QML `WorkflowProgressDialogQmlTest.cpp:552-575` prova que

### Riscos residuais a reportar

1. Importacao XLSX pode falhar por arquivo individualmente mesmo apos o fix do
   dir `data/`. Cabecalhos de exports antigos do SSA podem nao ser
   reconhecidos. O wizard deve capturar `result.diagnostic` por arquivo e
   exibir no `errorMessage` (o `SpreadsheetImportWorkflowPort` ja tem
   inventario tipado: `Applied`/`Failed`/etc em `:492-540`).
2. Windows OneDrive redirection pode causar paths longos >260 em
   `~/.ssaconsultarapida`. `std::filesystem::create_directories` lida com
   isso, mas registrar no report.
3. Deteccao first-run via `hasDatabase` deve checar existencia do ARQUIVO
   (`std::filesystem::is_regular_file`), nao so do dir, para nao pular o
   wizard quando o dir `data/` foi criado vazio por versao antiga.
4. Race condition: o wizard roda em thread separada (`QtConcurrent`) enquanto a
   UI continua responsiva. Garantir que `cancel()` use `std::stop_source`
   consistentemente (ver padrao `DatabaseSwitchViewModel`).
5. Relancamento: apos `launchWithDatabase`, o `QCoreApplication::quit` deve
